## 澄清：smartctl-ps3stor RPM 包为何不含 smartd
- 用户问"smartd 没有编译，正常吗？"实际：构建日志 1119-1143 行证明 smartd.cpp 被编译、链接（-o smartd），并被 `make install` 安装到 buildroot 的 /usr/sbin/smartd。
- 最终 rpm 包没有 smartd 是**设计如此、正常**：spec 的 %description 写明 "provides only the smartctl CLI"；上一轮为通过打包，在 spec %install 显式 `rm -f %{buildroot}%{_sbindir}/smartd` 等。
- 用户确认【需要】把 smartd 也打进包。已修改 `smartctl-ps3stor.spec`：
  - `%install` 不再删除 smartd/update-smart-drivedb/drivedb.h/配置/man，仅删除 /usr/share/doc/smartmontools 文档树。
  - `%files` 新增：`%{_sbindir}/smartd`、`%{_sbindir}/update-smart-drivedb`、`%config(noreplace) /etc/smartd.conf`、`%config(noreplace) /etc/smartd_warning.sh`、`%{_datadir}/smartmontools/drivedb.h`、`smartd.8*`、`update-smart-drivedb.8*`、`man5/smartd.conf.5*`。
  - 顺带修复了之前删除 drivedb.h 导致的 smartctl 识别能力退化。
  - `%description` 也改为说明包含 smartctl + smartd + drivedb.h + update-smart-drivedb。
- 用户确认【需要】smartd.service 也进包并自动启用。已修改 spec：
  - `%install` 写入自带的 `smartd.service`（上游 smartd.service.in 用 /usr/local 前缀不符，故自建；Type=simple + ExecStart=/usr/sbin/smartd -n，避免编译未链 libsystemd 时 notify 超时）。
  - `%files` 声明 `/usr/lib/systemd/system/smartd.service`（用绝对路径，不依赖 %{_unitdir} 宏，避免构建容器缺 systemd-rpm-macros）。
  - 添加 `%post`(daemon-reload + enable + start)、`%preun`(stop+disable on $1=0)、`%postun`(daemon-reload)，均带 `|| :` 容错；未用 %systemd_* 宏以避免额外 BuildRequires。
  - 更新 changelog（注意曾误生成重复条目，已清理）。
- 复查（用户要求"检查修复错误和bug"）：
  - 已逐项对照日志 make install 安装清单（logs.txt 1140-1163 行）与 %files：全部覆盖或已删除（doc 目录），无 unpackaged 风险；debug 文件自动进 debuginfo 子包。
  - 全部文件（spec/smartd.conf/smartd_warning.sh/smartd.service.in/workflow yml）均为 LF 换行，无 CRLF heredoc 隐患（曾专门脚本验证）。
  - heredoc 内容无行首 %、单引号定界符，$smartd_opts/$MAINPID 不会被 rpmbuild/shell 展开，安全。
  - %post/%preun/%postun 参数语义正确（卸载 $1=0 才 stop+disable；升级 $1=1 不中断）；RPM 会为脚本中 systemctl 自动加 Requires(post)。
  - 仓库 smartd.conf 默认启用 DEVICESCAN（第18行），有真实磁盘即可自动监控。
  - 待确认项（非 bug）：smartd.service 的 `ConditionVirtualization=no` 使 VM 中服务不启动（上游默认）；若系统无任何磁盘，%post start 会静默失败但 | 容错，不影响安装。
